# Idea Validation Framework

Structured approaches for evaluating ideas with research backing and data-driven decisions before committing significant resources.

## What's Inside

- **validation-checklist.md** - Pre-gate checklist: Is this idea ready for validation?
- **hypothesis-template.md** - Frame your idea as testable hypotheses
- **impact-assessment-template.xlsx** - Estimate the potential impact and resource requirements

## Why Validate First?

- **Fails fast** - Learn what won't work before building it
- **Saves resources** - Don't build for problems nobody has
- **Builds stakeholder confidence** - Decisions backed by data
- **De-risks decisions** - Evidence reduces organizational risk

## The Validation Workflow

```
Idea → Checklist → Hypothesis → Research Plan → 
Run Research → Analyze → Go/No-Go Decision
```

### Stage 1: Validation Checklist
**Ask:** "Is this idea clear and ready to test?"

Use the checklist to confirm:
- Problem is specific
- Stakeholders care
- Assumptions are identified
- Success criteria are measurable

### Stage 2: Hypothesis Template
**Ask:** "What exactly do we believe, and how will we test it?"

Frame your core assumptions and plan validation research:
- User problem assumptions
- Solution fit assumptions
- Adoption assumptions
- Implementation feasibility

### Stage 3: Run Research
**Ask:** "What does the data actually show?"

Pick your research method (survey, interviews, pilot) and execute systematically.

### Stage 4: Make Decision
**Ask:** "Do we proceed, pivot, or stop?"

- **Go** - Research confirmed our assumptions; move to project planning
- **Pivot** - Research showed we need to adjust; update and retest
- **Stop** - Research showed this won't work; kill the idea respectfully

## Common Scenarios

### Scenario 1: "We Should Use AI for [Something]"
1. Complete the **validation checklist** - Is the idea clear?
2. Use the **hypothesis template** - What exactly are we assuming about AI effectiveness?
3. Design a **small pilot** - Test with real students/teachers for 2-4 weeks
4. **Analyze results** - Did it actually work? Did adoption happen?
5. **Decide** - Go, pivot, or stop

### Scenario 2: "Let's Adopt [Tool] Schoolwide"
1. Complete the **validation checklist** - Do we know why we're adopting it?
2. Use the **hypothesis template** - What assumptions underlie this choice?
3. **Pilot with one department** - Test before rolling out to all 500 staff
4. **Gather feedback** - Teachers, students, admins
5. **Decide** - Full rollout, limited rollout, or different tool

### Scenario 3: "We Need Better [Process]"
1. Complete the **validation checklist** - What problem are we solving?
2. Use the **hypothesis template** - What's the root cause?
3. **Map current state** - How does it work today?
4. **Design small improvement** - Test one change with a small group
5. **Decide** - Scale if working, adjust if not

## Research Methods

### Quick & Cheap (< 1 week, minimal resources)
- **Survey** - Surveymonkey/Typeform to 20-50 people
- **Interview** - 1:1 calls with 5-10 key stakeholders
- **Data review** - Analyze existing data for patterns

### Medium (1-2 weeks, moderate resources)
- **Focus group** - Bring 8-12 people together to discuss
- **Two-week pilot** - Real users try the solution
- **Competitive analysis** - Study how others solved this

### Comprehensive (2-4 weeks, significant resources)
- **Four-week pilot** - Measure real usage and outcomes
- **Qualitative study** - Deeper interviews + observations
- **Full rollout test** - Department-level implementation

## Success Criteria Framework

**Before you start validation, define what success looks like:**

### Hard Metrics (Measurable)
- X% of teachers will use this tool at least weekly
- Adoption will reach X% of target users by month 3
- Impact will be measurable within X weeks

### Soft Metrics (Observable)
- User feedback will be generally positive (4+/5 rating)
- Teachers will report it saves time
- Integration will be smooth (minimal support tickets)

### Go/No-Go Thresholds
- If adoption < 30%, we stop
- If feedback is < 3.5/5, we pivot
- If implementation takes > 2x expected time, we reconsider

## Common Mistakes to Avoid

❌ **Starting research without clear questions**
→ Ask "What specifically do we need to learn?"

❌ **Only talking to enthusiasts**
→ Also talk to skeptics and neutral people

❌ **Ignoring negative feedback**
→ That's the most valuable data

❌ **Running pilot but ignoring results**
→ If research says "no," listen

❌ **Validating the wrong thing**
→ Validate if people want it, not just if it's technically possible
